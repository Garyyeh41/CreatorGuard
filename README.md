# CreatorGuard

**AI should guide. Humans should decide.**

CreatorGuard proposes local-first quality control for creative production. This repository contains the executable **rule-based SRT quality-checking prototype**. The broader AI review interface and ASUS UGen300 hardware integration are planned.

Competition context: Battlefield Lightning / Creator AI.

## Implemented prototype

The Python checker reads one SRT file and prints a JSON report. It checks:

- Cue index syntax and timestamp format.
- Invalid minute/second values and non-positive cue duration.
- Overlap between subtitle cues within the same file.
- Subtitle line count, line length, and missing subtitle text.

Default review thresholds are two lines per cue and 42 characters per line. These are configurable review heuristics, not universal subtitle requirements. The command-line option `--max-chars` adjusts line length; Python callers can also set `max_lines`.

**This prototype does not compare subtitles against singing or an audio track.** It does not detect bilingual meaning mismatches, missing lyric phrases, rendered subtitle layout problems, moons, or split-screen composition. No AI model or hardware accelerator is used by the current checker.

## Run locally

Requires Python 3.9 or newer. Uses only the Python standard library; no packages need to be installed.

From this repository's root:

```bash
python check_srt.py examples/valid.srt
python check_srt.py examples/review_needed.srt
python check_srt.py examples/review_needed.srt --max-chars 60
python -m unittest discover -s tests -v
```

On Windows, `py` can replace `python` if that is your available Python launcher.

To save a report:

```bash
python check_srt.py examples/review_needed.srt > review_report.json
```

The synthetic example has overlapping cues, a long line, and a cue with three lines. Example reports generated by the checker are in [examples/reports](examples/reports). They demonstrate this program's output and are not historical production evidence.

## Read the output

The JSON object contains `file`, `findings`, and `finding_count`. A finding identifies the source SRT cue number, severity, and issue. If the cue number itself is invalid, `cue` identifies the block position instead.

- `ERROR`: a structural problem, such as an invalid time range.
- `WARNING`: a condition for human review, such as an overlap or long line.

The process exits with code `1` when the report contains an `ERROR`, and `0` otherwise. **Exit code 0 does not mean the subtitle is correctly synchronized or free of warnings.** Review `findings` and the actual video/audio before deciding.

Input files must be UTF-8; UTF-8 BOM is supported. The checker does not edit the source file or send its content over the network.

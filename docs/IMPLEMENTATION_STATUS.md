# Implementation status

## Available now

`check_srt.py` is a deterministic, rule-based Python command-line tool. It processes one SRT file locally and produces a JSON report. The repository includes unit tests and synthetic examples.

Its overlap check compares timestamps of cues in the same SRT file. It has no reference audio, second-language comparison, speech model, visual model, or Premiere integration. A file can pass the format checks while still being out of sync with singing.

## Historical evidence versus executable features

Cases 01–05 illustrate issues encountered in real creative production. The historical corrected versions were produced or reviewed by the creator. These cases support the problem statement and proposed workflow; they are not successful automated detections by this code.

Case 05 retains the original 03:25–03:53 source segment, including its original sound, for human comparison. Missing English text at 03:28 and the incomplete ending at 03:50 are observations from the historical footage, not findings generated by this checker.

The Demo's proposed warning interface expresses the intended human-in-the-loop workflow: creator rules, checking, evidence/warning, and human decision.

## Planned integration

ASUS UGen300 is the proposed hardware target. Device integration and acceleration have not been implemented or tested here. No measured latency, accuracy, hardware compatibility, or accelerator benchmark is claimed.

Local-first AI checks are a development direction. The implemented SRT checker uses no network calls, but this property alone does not validate the privacy or performance of future AI components.

## Current limitations

- No alignment to vocals or audio.
- No bilingual semantic or missing-phrase comparison.
- No rendered subtitle positioning or visual scene checks.
- No automatic subtitle or video correction.
- No validation of cue numbering continuity or uniqueness.
- Character counts use Python string length, not rendered width.
- Warnings require human interpretation; exit code 0 can still include warnings.
- The CLI expects a readable UTF-8 input file; missing files and decoding failures raise Python exceptions.
